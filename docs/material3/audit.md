## Required screen review procedure

For each tracked entrypoint in `screen-audit.json`, review its child components and all states (loading, empty, offline, error, content, edit, navigation). For each applicable Material 3 component, record: the specific official component guidance, whether a recommendation or a mandatory rule, the chosen Compose API, deliberate deviations with rationale, accessibility checks, and automated/manual evidence. Only change the status to `reviewed` after storing evidence links. Do not treat an open PR as a completed fix.

Suggested source entrypoints:
- https://m3.material.io/get-started
- https://developer.android.com/develop/ui/compose/designsystems/material3
- https://developer.android.com/develop/ui/compose/accessibility/testing
- https://developer.android.com/studio/preview/compose-screenshot-testing-with-testsuites

This baseline covers **nine `*Screen.kt` files plus the application shell**, not the full component tree. Remaining tasks include custom component wrappers, current guideline interpretation for each state and viewport, approved visual baselines, and broader emulator tests.

## University login form alignment — 2026-11-06

Mail and BARS now use the same Compose Material 3 credential fields, button, checkbox and form spacing. The service title, browser option for mail and confirmation-code step for BARS remain distinct. This is an MPEI Lite product decision, not a claim that Google requires identical service login screens. The services still keep separate sessions and saved credentials.

Affected registry rules: M3-COMP-001, M3-TYPE-001, M3-ACCESS-001, M3-ADAPT-001 and M3-LAYOUT-001. The source reviewed for Material 3 components and theme typography is https://developer.android.com/develop/ui/compose/designsystems/material3. The form uses `OutlinedTextField`, `Checkbox`, `Button`, `TextButton` and `MaterialTheme` roles. The app shell supplies IME and system-inset padding.

An instrumented regression test covers required fields, checkbox-label interaction and IME submission. The test APK compiles, but the device's Compose runner throws `Exception handler was not found via a ServiceLoader` before executing this test; an existing Compose test fails identically. Both login screens were visually checked on the connected Redmi Note 9 Pro in dark theme. Remaining checks: a working instrumented runner, light theme, expanded width, large font, TalkBack reading order, and mail's configured-account login overlay. These rules remain `implementation-review-required`; this change is not a complete Material 3 audit.

## BARS confirmation-code delivery — 2026-11-06

The first code request now starts automatically when BARS accepts the password and opens the code step. The action shows sending progress, offers a retry if delivery fails, and says “send again” only after a successful request. This interaction is an MPEI Lite decision. A unit regression test covers the initial request and action labels.

Affected rules: M3-INPUT-001 and M3-ACCESS-001. Sources reviewed: https://m3.material.io/get-started and https://developer.android.com/develop/ui/compose/designsystems/material3. Android's SMS code autofill APIs apply to SMS messages (https://developer.android.com/reference/kotlin/androidx/compose/ui/autofill/ContentType); this BARS flow requests delivery through MAX. Notification reading would require the user's system-level notification-listener grant (https://developer.android.com/reference/android/service/notification/NotificationListenerService) and was not added. Live delivery, code confirmation, accessibility and large-font behavior remain unverified without a test account and working device test runner.

The mail message layer now lets the completed predictive gesture own its exit and skips the overlay's second exit spring. Ordinary Back still uses the overlay exit. ## Shared detail predictive-back preview — 2026-11-06

Mail and BARS details use a shared gesture-driven full-screen surface preview. During a gesture the detail scales toward 90%, shifts toward the swiped edge while leaving an 8dp gap, and reveals its mounted parent. Commit fades the detail away before closing it; cancellation restores full size. The mail folder tabs and list remain mounted behind the detail so the preview shows the actual destination. The outer app search/navigation remain outside the transformed detail, as required by MPEI-MAIL-001.

Affected rules: M3-MOTION-001, M3-SHAPE-001, M3-ADAPT-001, MPEI-MAIL-001 and MPEI-BARS-001. The scale and edge-gap values come from Android's full-screen surface and shared-element guidance at https://developer.android.com/design/ui/mobile/guides/patterns/predictive-back; the Compose gesture implementation follows https://developer.android.com/guide/navigation/custom-back/support-animations. The 28dp corner interpolation is an MPEI Lite choice based on its Material 3 theme, not a Google-specified numeric requirement. Shizuku's reference implementation uses separate activities with `android:enableOnBackInvokedCallback="true"` (https://github.com/RikkaApps/Shizuku/blob/master/manager/src/main/AndroidManifest.xml); that system cross-activity transition is not the app's in-screen mail/BARS route model. Unit tests cover transform bounds and swipe directions. Live gesture, cancellation, compact/expanded windows, large font, TalkBack and predictive-back visual continuity still require device verification; the rule statuses remain `implementation-review-required`.

## Mail detail search-bar visibility — 2026-11-06

Opening a mail message no longer requests a full-screen shell header. The shared mail search bar remains mounted above the detail and outside its predictive-back transform; the login page and composer still occupy the shell header. This enforces the MPEI Lite product rule MPEI-MAIL-001 (https://m3.material.io/components/search/overview), alongside M3-NAV-001 and M3-ADAPT-001 (https://developer.android.com/develop/ui/compose/designsystems/material3). A unit regression test covers detail, login, composer and inbox states. Live search from an open message, predictive-back continuity, large font, expanded width and TalkBack remain unverified on device; registry statuses remain `implementation-review-required`.

## Schedule search expansion — 2026-11-06

Schedule search now uses the same Material 3 `TopSearchBar` and `ExpandedFullScreenSearchBar` pair as mail, with one shared search-bar state and input field. The existing type filters, favorites, recent targets, live results, favorite controls and selected-timetable action remain in the expanded surface. The app shell supplies safe-area and keyboard padding; the collapsed schedule bar therefore has zero additional window insets. The agenda remains mounted behind the expanded search for a continuous collapse transition. The settings action moves into the collapsed search field, matching mail's field layout. A display-only text transformation preserves the selected timetable label when collapsed while retaining the query for reopening search.

Affected rules: M3-COMP-001, M3-MOTION-001, M3-INPUT-001, M3-ADAPT-001 and M3-ACCESS-001. The official search component behavior is described at https://developer.android.com/develop/ui/compose/components/search-bar and https://m3.material.io/components/search/overview; the display-only text transformation follows https://developer.android.com/develop/ui/compose/text/user-input; Material 3 Compose implementation guidance is at https://developer.android.com/develop/ui/compose/designsystems/material3. The instrumented smoke test compiles with assertions for expansion, filters, results, query retention and collapse. The connected Redmi Note 9 Pro was manually checked for expanded layout, live query, query retention, filter selection, toolbar collapse, settings access and system Back with the keyboard. The device's Compose test runner still fails before test bodies with `Exception handler was not found via a ServiceLoader`; the API 37 emulator cannot start because its 12 GB userdata partition exceeds the available AVD disk space. Motion continuity, predictive Back, expanded width, large font and TalkBack remain unverified; registry statuses remain `implementation-review-required`.

## Exchange folders and sender photos — 2026-11-06

The initial folder UI used a menu and hardcoded system folder entries; the later correction below replaces that navigation. Each loaded folder retains its in-memory page and scroll position while switching. Item folders use the captured `FindItem` and `GetItem` OWA forms; conversation folders use the existing conversation forms. Sender photos use the authenticated OWA persona endpoint for known sender addresses, with the existing initial avatar when Exchange has no image. Photos stay in memory and clear on sign-out. The supplied HAR was used for protocol shapes only; its account data is not in the repository.

Affected rules: M3-COMP-001, M3-NAV-001, M3-INPUT-001, M3-ACCESS-001, M3-ADAPT-001, M3-COLOR-001 and MPEI-MAIL-001. Official component and accessibility guidance reviewed: https://developer.android.com/develop/ui/compose/designsystems/material3, https://m3.material.io/components/tabs/overview, https://m3.material.io/components/menus/overview and https://developer.android.com/develop/ui/compose/accessibility/testing. The device Compose test runner still fails before test bodies with `Exception handler was not found via a ServiceLoader`. The HAR's photo sender uses a legacy Exchange address in the item list; its SMTP address arrives in `GetItem`, so the photo can appear in detail and in the list after that message has been opened. ## Mail folder tabs correction — 2026-11-06

The hardcoded Drafts, Deleted Items, Junk and Notes destinations and the “Папки” menu tab were removed. Inbox and Sent remain available at startup; all other tabs now come only from Exchange folder discovery. Discovery requests the `PidTagAttributeHidden` property and filters hidden and internal folders; the fallback also filters known internal names. The tabs show Material Symbols without visible labels, with a plain tooltip on long press and a folder name in accessibility semantics. The row keeps equal tab widths while icons fit and switches to Material 3's scrollable primary tab row when they do not. A discovered personal folder uses a generic folder symbol and its own tooltip/name. This is the requested MPEI Lite navigation choice, not a claim that Google mandates icon-only mail folders.

The API 35 emulator accessibility check in PR #135 exposed the tooltip anchor as an unlabeled 24dp icon inside each tab. The tooltip now wraps the complete Material 3 tab, so its anchor uses the tab's labeled touch target. The existing instrumented `mailFolderTabsAreAccessibleAndStateful` check covers this behavior; its CI result is recorded in the PR. This correction affects M3-ACCESS-001, M3-INPUT-001 and M3-LAYOUT-001. Source pages: https://developer.android.com/develop/ui/compose/components/tooltip, https://developer.android.com/develop/ui/compose/components/tabs and https://developer.android.com/develop/ui/compose/accessibility/testing.

Affected rules: M3-COMP-001, M3-NAV-001, M3-INPUT-001, M3-ACCESS-001, M3-ADAPT-001, M3-LAYOUT-001 and MPEI-MAIL-001. Exact official pages reviewed: https://developer.android.com/develop/ui/compose/components/tabs, https://developer.android.com/reference/kotlin/androidx/compose/material3/PrimaryScrollableTabRow.composable, https://developer.android.com/develop/ui/compose/components/tooltip and https://developer.android.com/develop/ui/compose/accessibility/semantics. Exchange's hidden-folder property is documented at https://learn.microsoft.com/en-us/exchange/client-developer/exchange-web-services/how-to-work-with-hidden-folders-by-using-ews-in-exchange. The icon assets come from https://github.com/google/material-design-icons/tree/master/symbols/web. Folder parsing and icon tab selection have regression coverage. On the Redmi Note 9 Pro, live discovery produced icon tabs, horizontal scrolling worked, and hidden internal folders were absent after the discovery correction. The Compose test runner remains blocked by `Exception handler was not found via a ServiceLoader` before test bodies run. Tooltip accessibility, large fonts, expanded width, keyboard/insets, folder content for every discovered tab and predictive-back continuity remain unverified. The design registry statuses remain `implementation-review-required`.

## Folder cache, loading state, grade selection and Settings back — 2026-11-07

The encrypted, account-scoped mail cache now stores each opened Exchange folder's pages and the discovered folder catalog. The folder list and pages restore after process restart; visiting a folder refreshes it while its downloaded messages remain on screen. Sign-out clears these files with the existing account cache. Empty folders show the existing Material 3 pull-to-refresh indicator as their only loading indicator. BARS 4.2 grade choices use the same connected-button spacing and shapes as the Settings mail sync interval choices. The single-digit buttons need wider content padding to make their visible shapes meet across the minimum touch targets. Settings opens in the shared full-screen predictive-back detail layer; the originating screen, including its app navigation bar or rail, stays mounted behind it. Its own scaffold handles safe drawing and IME insets.

Affected rules: M3-COMP-001, M3-MOTION-001, M3-ACCESS-001, M3-ADAPT-001, M3-INPUT-001, M3-LAYOUT-001 and the product rule MPEI-NAV-001. Exact official pages reviewed: https://developer.android.com/develop/ui/compose/components/pull-to-refresh, https://developer.android.com/reference/kotlin/androidx/compose/material3/ButtonGroup.composable, https://developer.android.com/reference/kotlin/androidx/compose/material3/ButtonGroupDefaults, https://developer.android.com/develop/ui/compose/system/predictive-back-setup, https://developer.android.com/guide/navigation/custom-back/support-animations, and https://developer.android.com/develop/ui/compose/designsystems/material3. The choice to show only the pull indicator and the full-shell Settings overlay are MPEI Lite decisions. An encrypted cache round-trip test passed on the Redmi Note 9 Pro, including separate folder pages, head-page merge, account isolation and account clearing. Manual checks showed Settings covering the app navigation bar, a Back swipe returning to the mounted schedule and to the still-expanded BARS planner, one loading indicator on entering Trash, Trash messages displayed immediately after an app restart, and BARS 4.2 grade buttons with close visual spacing matching the Settings group. The Compose UI regression test compiles but still fails before the test body with `Exception handler was not found via a ServiceLoader`, consistent with https://github.com/Kotlin/kotlinx.coroutines/issues/4782 on physical Android 16 devices. Gesture progress and cancellation, expanded width, large fonts, keyboard/insets and TalkBack remain unverified; the registry statuses remain `implementation-review-required`.
