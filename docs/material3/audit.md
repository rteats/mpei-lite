# Initial MPEI Lite Material 3 audit — 2026-11-05

**Status: not a completed compliance audit.** This is a baseline inventory and a set of recorded, previously reported discrepancies. It is deliberately not a Google certification. The `screen-audit.json` inventory is machine-checked to catch newly added `*Screen.kt` entry points that lack a review record. Other composables, dialogs, navigation transitions and WebView content must also be included in the manual audit.

## Redesign research — 2026-11-20

The [repository audit, source review and timetable proposal](redesign-research-2026-11-20.md) rechecks the earlier PRs against `main`, records the current navigation and motion gaps, and specifies evidence needed for the redesign. Registry statuses and screenshot references still require implementation review.

### Overlapping lessons and lesson-type icons

Each period now occupies one row of the existing timetable height. A cell with simultaneous lessons presents the first abbreviation and a count for the rest. Tapping it opens a list in the lesson sheet. Every entry has its own type, room and teacher where available, and opens the existing details and actions. The grid and picker use Outlined Material Symbols. MPEI Lite maps practice to `edit`, lecture to `hearing`, lab to `science`, and exams and other lesson types to `quiz`. The icon is decorative for accessibility because the lesson type is conveyed in the cell description and in the picker text.

Affected rules are M3-COMP-001, M3-COLOR-001, M3-TYPE-001, M3-ACCESS-001, M3-ADAPT-001 and M3-LAYOUT-001. Exact pages reviewed include [Material 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3), [clickable list items](https://developer.android.com/reference/kotlin/androidx/compose/material3/ListItem.composable), [Compose accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults), and [Material Symbols](https://developers.google.com/fonts/docs/material_symbols).

The overlap regression reproduced the threefold row height on the previous build. On the new build, six API 37 emulator tests passed, including fixed row height, choosing a lesson from an overlapping slot, large-font date headers and lesson-sheet restoration. The debug build, lint, 318 JVM tests, both Python policy checks and 20 Python tests passed. The signed build was installed in place over USB on a Redmi Note 9 Pro. On its loaded timetable, a three-lesson slot occupied one row, showed `+2`, listed all three entries with lecture and lab icons, and opened the selected lab's details. Six horizontal swipes on the phone produced 233 rendered frames, p50 19 ms, p95 44 ms and 27 missed deadlines in `dumpsys gfxinfo`. This debug sample has no matched comparison. The phone's Compose instrumentation still stops in its coroutine ServiceLoader before running the UI assertions. Dark mode, expanded-window rendering and manual TalkBack traversal remain open for this change.

### Android system navigation bar

MPEI Lite extends its Material 3 `surfaceContainer` color behind Android's navigation buttons and uses the system's light or dark button appearance for contrast. The main activity draws the color in the tappable navigation insets, including the side inset when Android places the buttons there. Gesture navigation uses a transparent system bar.

Affected rules are M3-COLOR-001 and M3-ADAPT-001. Android documents the edge-to-edge drawing and contrast behavior in [Compose system bar protection](https://developer.android.com/develop/ui/compose/system/system-bars), [Compose insets](https://developer.android.com/develop/ui/compose/system/insets), and the [edge-to-edge codelab](https://developer.android.com/codelabs/edge-to-edge). The surface role follows [Material 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3).

An API 37 emulator screenshot test verified the exact theme color behind the buttons. With gesture navigation enabled, the destination, schedule search and Settings smoke checks passed. On a Redmi Note 9 Pro, the system strip and app bar matched in light and dark modes, Home was readable in both, and system Back returned from Settings after switching themes. The original theme was restored after testing. Landscape and older Android releases still need device coverage.

### Timetable viewport, week gestures and mail tab alignment

MPEI Lite fits four days on the Redmi Note 9 Pro at its default text size. Period rows share the available height and continue to scroll when their scaled minimum height exceeds the viewport. Lectures use the Outlined `school` symbol. The seventh standard period starts at 20:30 and ends at 22:00. Extra start times from the schedule feed are still rendered. [MPEI timetable regulations, §6.6](https://mpei.ru/AboutUniverse/OficialInfo/Orders2022/MPEI-22-838-pril2.pdf)

The week heading uses a finger-tracked pager and moves the day grid when the selected week settles. Tapping the heading opens the date picker. Pulling down on the grid refreshes the visible week. The heading also exposes accessibility actions for refresh and adjacent weeks. Mail keeps the Material primary indicator centered within the selected tab as the folder strip scrolls. Affected rules are M3-COMP-001, M3-MOTION-001, M3-ACCESS-001, M3-ADAPT-001, M3-INPUT-001 and M3-LAYOUT-001. [Compose pager](https://developer.android.com/develop/ui/compose/layouts/pager), [Material pull to refresh](https://developer.android.com/develop/ui/compose/components/pull-to-refresh), [Material tabs](https://developer.android.com/develop/ui/compose/components/tabs), [Compose accessibility semantics](https://developer.android.com/develop/ui/compose/accessibility/semantics), [Material Symbols](https://developers.google.com/fonts/docs/material_symbols)

The updated Redmi build showed four date columns, reached the 20:30 row, switched weeks in both directions and issued a network refresh after a downward swipe. Tapping the heading opened the date picker, and system Back returned to the same week. The Sent icon and its pill centers matched within one pixel. API 37 emulator checks passed for four columns with gesture insets, viewport height, calendar order across Sunday, finger tracking and cancellation, refresh, the mail indicator and tab accessibility. Dark theme, landscape, expanded-window layouts and manual TalkBack traversal still need device coverage.

### Timetable frame pacing

The week heading keeps one pager across changes. The grid advances at most one day column per frame when following a settled heading, and nearby columns use Compose lazy prefetch. Empty period backgrounds are drawn together per day. The heading and occupied cells retain their existing layout, touch targets and accessibility nodes.

A Redmi Note 9 Pro debug trace attributed the week-switch hitch to the grid measuring the destination days in one frame. The swipe regression covers cancellation, switching in both directions, matching the grid to the heading, and opening the date picker after switching. Affected rules are M3-MOTION-001, M3-ADAPT-001, M3-ACCESS-001 and M3-LAYOUT-001. [Compose performance practices](https://developer.android.com/develop/ui/compose/performance/bestpractices), [Compose pager](https://developer.android.com/develop/ui/compose/layouts/pager), [Custom Compose layouts](https://developer.android.com/develop/ui/compose/layouts/custom), [Compose drawing modifiers](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers)

## Required screen review procedure

For each tracked entrypoint in `screen-audit.json`, review its child components and all states (loading, empty, offline, error, content, edit, navigation). For each applicable Material 3 component, record: the specific official component guidance, whether a recommendation or a mandatory rule, the chosen Compose API, deliberate deviations with rationale, accessibility checks, and automated/manual evidence. Only change the status to `reviewed` after storing evidence links. Do not treat an open PR as a completed fix.

Suggested source entrypoints:
- https://m3.material.io/get-started
- https://developer.android.com/develop/ui/compose/designsystems/material3
- https://developer.android.com/develop/ui/compose/accessibility/testing
- https://developer.android.com/studio/preview/compose-screenshot-testing-with-testsuites

This baseline covers **nine `*Screen.kt` files plus the application shell**, not the full component tree. Remaining tasks include custom component wrappers, current guideline interpretation for each state and viewport, approved visual baselines, and broader emulator tests.

## University login form alignment — 2026-11-06

Mail and BARS now use the same Compose Material 3 credential fields, button, checkbox and form spacing. The service title, browser option for mail and confirmation-code step for BARS remain distinct. This is an MPEI Lite product decision, not a claim that Google requires identical service login screens. The services still keep separate sessions and saved credentials.

Affected registry rules: M3-COMP-001, M3-TYPE-001, M3-ACCESS-001, M3-ADAPT-001 and M3-LAYOUT-001. The source reviewed for Material 3 components and theme typography is https://developer.android.com/develop/ui/compose/designsystems/material3. The form uses `OutlinedTextField`, `Checkbox`, `Button`, `TextButton` and `MaterialTheme` roles. The app shell supplies IME and system-inset padding.

An instrumented regression test covers required fields, checkbox-label interaction and IME submission. The test APK compiles, but the device's Compose runner throws `Exception handler was not found via a ServiceLoader` before executing this test; an existing Compose test fails identically. Both login screens were visually checked on the connected Redmi Note 9 Pro in dark theme. Remaining checks: a working instrumented runner, light theme, expanded width, large font, TalkBack reading order, and mail's configured-account login overlay. These rules remain `implementation-review-required`; this change is not a complete Material 3 audit.

## BARS confirmation-code delivery — 2026-11-06

The first code request now starts automatically when BARS accepts the password and opens the code step. The action shows sending progress, offers a retry if delivery fails, and says “send again” only after a successful request. This interaction is an MPEI Lite decision. A unit regression test covers the initial request and action labels.

Affected rules: M3-INPUT-001 and M3-ACCESS-001. Sources reviewed: https://m3.material.io/get-started and https://developer.android.com/develop/ui/compose/designsystems/material3. Android's SMS code autofill APIs apply to SMS messages (https://developer.android.com/reference/kotlin/androidx/compose/ui/autofill/ContentType); this BARS flow requests delivery through MAX. Notification reading would require the user's system-level notification-listener grant (https://developer.android.com/reference/android/service/notification/NotificationListenerService) and was not added. Live delivery, code confirmation, accessibility and large-font behavior remain unverified without a test account and working device test runner.

## Shared detail predictive-back preview — 2026-11-06

Mail and BARS details use a shared gesture-driven full-screen surface preview. During a gesture the detail scales toward 90%, shifts toward the swiped edge while leaving an 8dp gap, and reveals its mounted parent. Commit fades the detail away before closing it; cancellation restores full size. The mail folder tabs and list remain mounted behind the detail so the preview shows the actual destination. The outer app search/navigation remain outside the transformed detail, as required by MPEI-MAIL-001.

Affected rules: M3-MOTION-001, M3-SHAPE-001, M3-ADAPT-001, MPEI-MAIL-001 and MPEI-BARS-001. The scale and edge-gap values come from Android's full-screen surface and shared-element guidance at https://developer.android.com/design/ui/mobile/guides/patterns/predictive-back; the Compose gesture implementation follows https://developer.android.com/guide/navigation/custom-back/support-animations. The 28dp corner interpolation is an MPEI Lite choice based on its Material 3 theme, not a Google-specified numeric requirement. Shizuku's reference implementation uses separate activities with `android:enableOnBackInvokedCallback="true"` (https://github.com/RikkaApps/Shizuku/blob/master/manager/src/main/AndroidManifest.xml); that system cross-activity transition is not the app's in-screen mail/BARS route model. Unit tests cover transform bounds and swipe directions. Live gesture, cancellation, compact/expanded windows, large font, TalkBack and predictive-back visual continuity still require device verification; the rule statuses remain `implementation-review-required`.

## Mail folder tabs correction — 2026-11-06

The hardcoded Drafts, Deleted Items, Junk and Notes destinations and the “Папки” menu tab were removed. Inbox and Sent remain available at startup; all other tabs now come only from Exchange folder discovery. Discovery requests the `PidTagAttributeHidden` property and filters hidden and internal folders; the fallback also filters known internal names. The tabs show Material Symbols without visible labels, with a plain tooltip on long press and a folder name in accessibility semantics. The row keeps equal tab widths while icons fit and switches to Material 3's scrollable primary tab row when they do not. A discovered personal folder uses a generic folder symbol and its own tooltip/name. This is the requested MPEI Lite navigation choice, not a claim that Google mandates icon-only mail folders.

The API 35 emulator accessibility check in PR #135 exposed the tooltip anchor as an unlabeled 24dp icon inside each tab. The tooltip now wraps the complete Material 3 tab, so its anchor uses the tab's labeled touch target. The existing instrumented `mailFolderTabsAreAccessibleAndStateful` check covers this behavior; its CI result is recorded in the PR. This correction affects M3-ACCESS-001, M3-INPUT-001 and M3-LAYOUT-001. Source pages: https://developer.android.com/develop/ui/compose/components/tooltip, https://developer.android.com/develop/ui/compose/components/tabs and https://developer.android.com/develop/ui/compose/accessibility/testing.

Affected rules: M3-COMP-001, M3-NAV-001, M3-INPUT-001, M3-ACCESS-001, M3-ADAPT-001, M3-LAYOUT-001 and MPEI-MAIL-001. Exact official pages reviewed: https://developer.android.com/develop/ui/compose/components/tabs, https://developer.android.com/reference/kotlin/androidx/compose/material3/PrimaryScrollableTabRow.composable, https://developer.android.com/develop/ui/compose/components/tooltip and https://developer.android.com/develop/ui/compose/accessibility/semantics. ## Folder cache, loading state, grade selection and Settings back — 2026-11-07

The encrypted, account-scoped mail cache now stores each opened Exchange folder's pages and the discovered folder catalog. The folder list and pages restore after process restart; visiting a folder refreshes it while its downloaded messages remain on screen. Sign-out clears these files with the existing account cache. Empty folders show the existing Material 3 pull-to-refresh indicator as their only loading indicator. BARS 4.2 grade choices use the same connected-button spacing and shapes as the Settings mail sync interval choices. The single-digit buttons need wider content padding to make their visible shapes meet across the minimum touch targets. Settings opens in the shared full-screen predictive-back detail layer; the originating screen, including its app navigation bar or rail, stays mounted behind it. Its own scaffold handles safe drawing and IME insets.

Affected rules: M3-COMP-001, M3-MOTION-001, M3-ACCESS-001, M3-ADAPT-001, M3-INPUT-001, M3-LAYOUT-001 and the product rule MPEI-NAV-001. The choice to show only the pull indicator and the full-shell Settings overlay are MPEI Lite decisions. An encrypted cache round-trip test passed on the Redmi Note 9 Pro, including separate folder pages, head-page merge, account isolation and account clearing. Manual checks showed Settings covering the app navigation bar, a Back swipe returning to the mounted schedule and to the still-expanded BARS planner, one loading indicator on entering Trash, Trash messages displayed immediately after an app restart, and BARS 4.2 grade buttons with close visual spacing matching the Settings group.
